# Работа над проектом

Начать с README, [карты проекта](docs/repository-guide.md) и локальных правил
AGENTS.md, если они есть. Проверить предметную область и авторитетные документы
перед переносом кода между приложениями или репозиториями.

1. Создать отдельную ветку от актуальной основной ветки.
2. Ограничить изменение одной связанной задачей. Разделять код по предметным
   модулям с явными контрактами, сохранять существующие точки входа.
3. Выполнить проверки затронутого кода из карты проекта и README. Не заменять
   результат запуска предположением; описать ограничения окружения.
4. Открыть запрос на слияние: проблема, результат, изменённые границы и проверки.
   Для рефакторинга указать, как проверена совместимость.

Сохранять исходные LICENSE / NOTICE и происхождение перенесённых компонентов.
Использовать синтетические тестовые данные; секреты и персональные данные в git
не добавлять. Правила приёмки и выпуска определяются документами самого проекта.
