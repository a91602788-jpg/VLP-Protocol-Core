# VLP Protocol Core

**Открытый исследовательский проект нового защищённого сетевого протокола.**

[English](README.md) · [220 пунктов](docs/requirements/README.md) · [Семь ядер](docs/architecture/engineering-cores.md) · [Источники](docs/research/source-register.md) · [OSS-кандидаты](docs/research/oss-candidates.md)

VLP исследует передачу данных с явно определённой семантикой доставки, ограничением ресурсов, аутентифицированным управлением соединением и измеримым снижением распознаваемости трафика.

## Текущий этап

Сейчас оформлены структура исследования и реестр требований. Research Gate ещё не проведён. Транспорт, криптографическая основа и язык реализации остаются кандидатами. Исполняемой реализации, утверждённой версии Wire Format, результатов испытаний и независимого аудита пока нет.

Состояние проекта отражено также в [project-status.json](docs/project-status.json).

## Мобильная связь и разные типы узлов

В [исследовательском предложении](docs/research/deployment-profiles.md) рассматриваются связи сервер — сервер, телефон — сервер, телефон — телефон и устройство — сервер. Разделены три решения: что обещает доставка данных, кто участвует в маршруте и где заканчивается шифрование, какой транспорт несёт соединение.

Прямой путь, непрозрачный для содержимого ретранслятор, многослойный маршрут и асинхронная mix-сеть остаются кандидатами для разных сценариев. Адаптация скорости, энергопотребления и маршрута должна соблюдать заранее выбранные требования безопасности и конфиденциальности. Миграция, переподключение и восстановление прикладной операции рассматриваются отдельно.

## Семь инженерных ядер

| Ядро | Область ответственности |
| --- | --- |
| 01 — Protocol Core | Семантика, роли, форматы, состояния, версии и расширения |
| 02 — Transport | Доставка, потоки, перегрузка, сетевые пути и MTU |
| 03 — Cryptography | Шифрование, ключи, целостность, Nonce и разделение контекстов |
| 04 — Handshake | Установка соединения, доверие, аутентификация и согласование параметров |
| 05 — Camouflage | Наблюдаемое поведение трафика и стоимость его изменения |
| 06 — Data Plane | Пакеты, фреймы, каналы, мультиплексирование и буферизация |
| 07 — Security | Модель угроз, противодействие атакам и доказательные проверки |

Privacy, Control Plane, производительность, устойчивость и развитие протокола рассматриваются сквозным образом. Семь ядер не означают семь отдельных сервисов или утверждённых пакетов кода.

## Все 220 пунктов сохранены

У каждого исходного пункта есть постоянный идентификатор `VLP-REQ-001` … `VLP-REQ-220`, исходное русское название, английский перевод, основная область ответственности и статус `OPEN`.

Повторяющиеся темы не удалены: для них отмечены пересечения. Альтернативы вроде UDP/TCP, PSK/сертификатов, 0-RTT, P2P и multipath требуют отдельных решений. Включение в реестр означает обязательность рассмотрения, а не обязательство включить все функции в первый выпуск.

## Порядок разработки

1. **Research** — требования, источники, альтернативы, угрозы и критерии проверки.
2. **Research Gate** — решение по доказательствам с результатом PASS, CONDITIONAL PASS или FAIL.
3. **VLP-0001 Architecture / VLP-0002 Packet Wire Format / VLP-0003 Handshake** — согласованные технические спецификации после разрешённого перехода.
4. **Specification Review** — проверка согласованности и безопасности спецификаций.
5. **Implementation Approval** — отдельное зафиксированное разрешение на реализацию.

Полный порядок и ограничения переходов: [decision-process.md](docs/process/decision-process.md). Слияние изменений документации само по себе не разрешает реализацию протокола.

## Использование существующего открытого кода

Можно использовать готовые компоненты, если проверены их назначение, лицензия, зависимости, сопровождение и безопасность. В [каталоге кандидатов](docs/research/oss-candidates.md) отделены потенциальные компоненты от эталонов для сравнения. Ни одна запись пока не означает внедрение.

Собственный транспорт поверх UDP, Noise, Rust и совместное планирование доставки и маскировки рассматриваются как исследовательские кандидаты. Их преимущества ещё нужно сопоставить с существующими решениями.
